# ts-in-types

The real TypeScript 7 compiler (its Go source, microsoft/TypeScript v7.0.2)
running inside the TypeScript type checker (tsrs), on the go-in-types engine.
No Lua in between (that was `../ts-in-lua-in-types`). Read `docs/PLAN.md`,
then `vendor/go-in-types/docs/PLAN.md`, `DESIGN.md` and `LESSONS.md`.

## Repos

- `vendor/go-in-types`: submodule, URL `../go-in-types` (the sibling
  checkout `/Users/gabrielperez/Documents/go-in-types` is canonical). Engine
  work (front end, reference, overlays, type runtime, emitter) is committed
  there on a branch and merged by the planner, never inside the submodule
  checkout. Then bump the pointer here:
  `git -c protocol.file.allow=always submodule update --remote vendor/go-in-types`
  (`chore: bump go-in-types`). Its nested `vendor/typescript` was initialised
  from the local clone; never re-clone it from GitHub.
- The tsgo overlays and harness live in go-in-types (`overlay/`, config
  `tsgo`; `scripts/tsgo-ir.ts` builds the IR). TypeScript-specific harness
  logic that doesn't belong in the engine lives here.

## Scripts (stage 3)

- `node scripts/oracle.ts [--verify]`: `oracle/expected/<lib>/<input>.out`
  and `oracle/manifest.json` from native tsc (format in `scripts/inputs.ts`).
- `node scripts/ref.ts [--lib L] [--only S] [--jobs N] [--image]`: the
  inputs on the go-in-types reference, compared with the oracle. The engine
  is `$GO_IN_TYPES` or the submodule (`scripts/engine.ts`); the IR is
  rebuilt when stale. Use `GO_IN_TYPES=<go-in-types worktree>` while
  working on engine fixes.
- `node scripts/boot.ts`: boot images `image/<lib>.json` (git-ignored);
  rebuild after the IR changes (a stale image fails to restore).
- `node scripts/profile.ts` then `vp check --fix`: `docs/PROFILE.md` tables
  and `oracle/profile.json`.
- Jobs: ~6–8 worker threads; other agents share the machine.

## Rules

- Conventional Commits; end messages with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Never push and never add remotes.
- The oracle is the native `tsc` 7.0.2 binary (`node_modules/.bin/tsc`),
  run in a temp dir (inside the repo it picks up `tsconfig.json`).
- "In types" means tsrs; heavy tsrs jobs go through
  `vendor/go-in-types/scripts/heavy.sh` (two machine-wide slots).
- Generated files are marked as such and regenerated by a script.
- Scratch in `.run/` (git-ignored).
- Before committing: `vp check --fix`, `vp run check`, `vp test`.
